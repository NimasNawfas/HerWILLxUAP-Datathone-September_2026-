# HerWILL × UAP Datathon 2026 — Toxicity Classification (3 classes, Macro-F1)

**Author:** Md. Mahmudul Kabir Himel (BRAC University) — code submission for the Kaggle competition.

## What this is
One self-contained, resumable notebook (`datathon_v3.ipynb`) that reads the raw `train.csv` / `test.csv`, cleans the text,
trains an **ensemble system** with K-fold out-of-fold (OOF) predictions, stacks it, tunes per-class thresholds and writes the
two submission files. **Only the provided competition data is used.** Pretrained checkpoints (allowed by the rules) are fine-tuned
on the training set; no external labeled or unlabeled datasets, no hand labeling, and the `id` column is **never** used as a feature
(it is only used to write the submission file).

**Note on ids:** we observed that the `id` column correlates with the source ordering of the data. Following the organizers' guidance
that solutions should use the comment text itself, we deliberately did not use ids or their neighbours in any model, feature or
post-processing step.

## Pipeline
| Stage | Model | Folds | Notes |
|---|---|---|---|
| 1 | TF-IDF (word 1–2g + char 3–5g) + LinearSVC, Platt-calibrated | 5 | TF-IDF fitted inside each fold only |
| 2 | XLM-RoBERTa-large (≈560M params) | 4 | 4 epochs, layer-wise LR decay, label smoothing, class-balanced loss |
| 3 | MuRIL-base-cased (≈238M) | 5 | 3 epochs, LLRD + EMA, noise-aware sample weights |
| 4 | mDeBERTa-v3-base (≈279M) | 5 | 3 epochs, LLRD + EMA, noise-aware sample weights, fp16 stability probe |
| 5 | Stacker (LogReg / HistGradientBoosting on model log-probs + text meta-features) + per-class thresholds | 5 (CV over OOF) | thresholds validated with nested CV |
| add-on | Exact-duplicate text lookup against train labels | – | applied only because it improved OOF Macro-F1 (+0.002) |
| add-on | Per-script (Bangla vs Latin) thresholds | – | **tested and rejected** (nested-CV gain −0.004); kept in the notebook as a documented negative result |

All hyper-parameters are in the configuration cell and are printed in the run log; `METHODOLOGY.md` (auto-generated) lists architecture,
parameter counts and hyper-parameters per model.

## How to run (reproduce)
1. Open `datathon_v3.ipynb` in **Google Colab** with a **T4 GPU** runtime (Runtime → Change runtime type → T4).
2. Upload `train.csv` and `test.csv` to `/content/` (or place them in `/content/data`).
3. *(Optional dry run, ~10–15 min)* set `SMOKE_TEST = True` in the configuration cell and Run all — this exercises every stage on a tiny subset.
4. Set `SMOKE_TEST = False`, set `HOURS_LEFT` (default 9) and **Run all**.
5. Outputs are written to `/content/datathon_run/` (or `datathon_run/` on Google Drive if it mounts):
   `submissions/submission_A_stack_thresholds.csv`, `submissions/submission_B_blend_thresholds.csv`, the `_twin` versions produced by the
   duplicate-lookup cell, `run_log.txt`, `METHODOLOGY.md`, `thresholds.json`.
6. The run is **resumable**: finished folds are saved and skipped after a disconnect — re-run all cells.

**Runtime (measured, Colab T4):** SVM ≈ 3 min · XLM-R-large ≈ 33 min/fold (≈ 2.2 h) · MuRIL ≈ 10 min/fold · mDeBERTa ≈ 15 min/fold ·
stacking ≈ 1 min → **≈ 4.4 h end to end**. Results are reproducible up to GPU non-determinism (fixed seeds, saved fold assignment).

## Results (honest, out-of-fold over all 47,737 labeled rows)
| Model | OOF Macro-F1 |
|---|---|
| TF-IDF + SVM | 0.5116 |
| MuRIL-base | 0.5506 |
| mDeBERTa-v3-base | 0.5629 |
| XLM-R-large | 0.5730 |
| Weighted blend + thresholds (nested CV) | 0.6006 |
| Stacker (HistGB) + thresholds (nested CV) | **0.6037** |
| + exact-duplicate lookup | ≈ +0.002 |

Submission A = stacker + thresholds (+ duplicate lookup), Submission B = weighted blend + thresholds (+ duplicate lookup).

**Selected final Kaggle submissions:** `submission_A_stack_thresholds_twin.csv` and `submission_B_blend_thresholds_twin.csv`.
**Public leaderboard (40% of test):** best 0.6043, consistent with the nested-CV estimate above.

## Notes / limitations
* Labels are noisy (e.g. clearly positive comments labeled *Explicitly Toxic*); this limits every text model and motivated the label smoothing and
  noise-aware weighting. The Bangla-script half of the data scores lower (≈0.51 F1) than the Latin-script half (English + romanized Bangla, ≈0.63);
  a Bangla-specific model is the obvious next step.
* Google Drive mounting failed in our Colab session, so outputs were written to the local `/content/datathon_run/` and downloaded manually.
